# OctoFit Tracker architecture

OctoFit Tracker is a three-tier application for a school fitness program. The starter code includes API contracts and intentionally incomplete implementation points so you can use GitHub Copilot agent mode in a test-driven loop.

![Three-tier OctoFit architecture](../.github/images/octofit-architecture.svg)

## Tier boundaries

- **Presentation tier**: React 19, Vite, React Router, Bootstrap, and a shared API client in `octofit-tracker/frontend/src`.
- **Logic tier**: Express and TypeScript routes/services in `octofit-tracker/backend/src` expose `/api/*` behavior on port `8000`.
- **Data tier**: Mongoose models and seed data in `octofit-tracker/backend/src/models` and `src/scripts/seed.ts` persist to MongoDB on port `27017`.

## Ports and environment rules

- MongoDB: `27017`
- Express API: `8000`
- Vite frontend: `5173`
- The browser calls relative `/api` paths. Vite proxies them to `http://localhost:8000`, so the unauthenticated API port stays private in Codespaces. `VITE_API_BASE_URL` can override the base URL.

## API contract

| Capability | Method and path | Expected behavior |
| --- | --- | --- |
| Activity tracking | `GET /api/activities`, `POST /api/activities` | List and create valid activity records. POST accepts `userId`, `teamId`, `type`, and `minutes`; `userId` and `teamId` must be well-formed IDs for an existing user and team; otherwise respond with a deliberate 4xx (never a 500 from a cast error). A created activity stores the submitted `user`, `team`, `type`, and `minutes` plus computed `points` and `occurredAt`. |
| Teams | `GET /api/teams`, `POST /api/teams` | List and create teams with members. Created and listed teams keep the submitted `name` and `mascot`. Reject a team without a name with `400`. |
| Leaderboard | `GET /api/leaderboard` | Return teams ordered by the sum of their activity points, highest first. Each entry has `teamName`, `totalPoints`, and a 1-based `rank`. |
| Workout suggestions | `GET /api/workouts/suggestions/:userEmail` | Recommend workouts from recent activity patterns for the matching seeded user's email address. The first suggestion's `focus` matches that user's goal or recent activity, with a `reason` explaining why. An email with no matching user returns a deliberate 4xx (for example, `404`). |

## Implementation decisions

Record your plan here before editing code.

- Presentation tier decision:
The presentation tier will use React route components and fetch from relative /api endpoints, rendering loading, empty, and error states so the UI matches the accessibility contract.

- Logic tier decision:
The logic tier will keep HTTP routing thin and push validation, business rules, and aggregation into the service layer, returning deliberate 4xx responses for invalid input and missing data.

- Data tier decision:
The data tier will use schema-level validation and seed scripts to create consistent user, team, activity, and workout data so the API contract is determinisitc in tests and dev

- Activity tracking approach:
Activities will be created via a validated service that checks user/team existence, rejects malformed IDs with 4xx responses, and stores the submitted fields plus computed points and timestamp

- Team management approach:
Teams will require a name and mascot, default to an emptry array, and preserve member references through Mongoose while returning 400 when a team payload is invalid

- Leaderboard approach:
Leaderboard will require a team name, team's total activity points, and a rank position determined by activity points; sorted highest ranking to lowest.

- Workout suggestions approach:
Suggestions generated by finding the user via email, matching their recent activity or fitness goal to a workout focus, and returned a ranked list with a reason string; unknown users result in a deliberate 4xx.

## Test plan

Record the commands you run and what each failure means.

- Data-tier command: `npm run test:data --prefix octofit-tracker/backend`
Validates Mongoose schema and seed data. Failure means required fields, relationships, or idempotent seed behavior are still incorrect

- API command: `npm run test:api --prefix octofit-tracker/backend`
Verifies the /api contract for activity creation, team creation, leaderboard sorting, and workout suggestions. Failure means the backend logic is not matching the required HTTP behavior

- Frontend command: `npm test --prefix octofit-tracker/frontend`
Veries the React app requests and renders real API data, including loading, empry, and error states. Failure means the UI is still a placeholder or not handling API responses correctly.

- Backend build command: `npm run build --prefix octofit-tracker/backend`
Catches TypeScript errors in models, services, and route logic before the app is considered stable

- Frontend build command: `npm run build --prefix octofit-tracker/frontend`
Ensures React/Vite app complies with the expected data-fetching code and accessible UI patterns.
